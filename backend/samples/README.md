# Bundled sample files

Three small files used by the 2D Denoising Lab and the tests. They are demonstration inputs. Only files whose terms of use could be established are bundled.

| File | What it is | Where it comes from | Terms | What was checked |
| --- | --- | --- | --- | --- |
| `chest_ct.png` (512 x 512, 8 bit) | Slice 50 (zero-based) of the chest CT series `LIDC-IDRI-0709` (100 axial slices, 0.54 mm pixels, 3 mm slices): stored values converted to Hounsfield units with the DICOM rescale, displayed with the -600/1500 HU lung window and saved as an 8-bit PNG. The Hounsfield values and the DICOM header are **not** in the file. | The Cancer Imaging Archive, collection LIDC-IDRI (Armato SG III et al., *Medical Physics* 2011; data citation DOI 10.7937/K9/TCIA.2015.LO9QL9SX). Produced by `python download_data.py --ct-series <series folder>` from the local copy of the series; the generator never replaces an existing `chest_ct.png` with different pixels unless `--overwrite-chest-ct` is given, and `test_download_data.py` checks (when the local series is present) that the shipped file is exactly its slice 50. | **CC BY 3.0**, the licence of the collection on The Cancer Imaging Archive and the licence text shipped with the series. Attribution is required: cite the collection when you reuse this image. | The PNG carries no metadata (no text chunk). The header of the series says the patient identity was removed (`PatientIdentityRemoved = YES`). The local series equals the public record of the collection at the level of its metadata (series and study UIDs, modality, scanner, software version, image count, total size); its files were **not** hashed against a fresh download. |
| `cell_phase.png` (550 x 660, 8 bit) | A single cell floating in saline, a quantitative phase image from digital holography, with a banding artefact in the background. A microscopy image: not tissue and not radiological. | scikit-image's `data.cell()` (a quantitative phase image reconstructed with the Python library `qpformat`; Müller et al., *Optics Express* 2018, DOI 10.1364/OE.26.010729). | CC0 (public-domain dedication) according to the documentation of `data.cell()`, read again on 2026-10-27 (the documentation names no copyright holder). | The statement of the documentation was read. Pixel equality of the file with `data.cell()` was **not** tested (the file was not cached locally and was not downloaded). |
| `synthetic_ct_scan.dcm` (256 x 256) | A synthetic phantom: two concentric discs (about 40 HU and 400 HU) on -1000 HU with Gaussian noise of 15 HU (fixed seed), stored as a DICOM CT slice with RescaleSlope 1 and RescaleIntercept -1024. Not an anatomical image. | Generated by `download_data.py` in this repository. It has no pixel spacing or orientation, so the series loader cannot read it (it is meant for the 2D lab). |

## A file that is no longer bundled

`head_ct.png` (first published as `brain_mri.png`) was slice 5 of scikit-image's `data.brain()`, itself a 10-slice subset of the University of North Carolina Volume Rendering Test Data Set. It was removed from the bundle on 2026-10-27 **because its terms of use could not be verified at the source**: scikit-image's documentation states neither the modality nor the licence, the Stanford archive page that lists the data set could not be opened (connection refused, two attempts), and the only statement of terms found was a secondary web summary. A copy is kept outside the repository. The file was published earlier (as `brain_mri.png`, on `main` since 2026-10-07 and in the history of this branch), and removing it from the current tree does not remove it from that history. The API no longer lists it; the identifiers `brain_mri` and `head_ct` answer 404.

## Not in this repository

The CT series behind the benchmarks, `LIDC-IDRI-0709` (100 axial slices), comes from The Cancer Imaging Archive under CC BY 3.0 (DOI 10.7937/K9/TCIA.2015.LO9QL9SX) and stays local. Its identity with the public series was compared at the level of metadata (series and study UIDs, modality, manufacturer, model, software version, image count and the total size of the 100 files, all equal to TCIA's public record); file hashes were not compared with a fresh download. The recorded runs store the SHA-256 of every file so anyone can compare their own copy.
